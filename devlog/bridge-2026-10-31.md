# bridge-core 2026-10-31（语音闭环 + 人设单真源）

## 目标
把"微信语音收发"和"控制台"从 fishdesk 独立 exe 迁到 DSH 插件化 monorepo：
`packages/bridge-core`（能力层）+ `packages/console-web`（DSH 前端控制台）。

## 目录
- `packages/bridge-core/voice/audio.py`：silk→pcm、pcm→wav、wav 16k 读取+重采样
- `packages/bridge-core/voice/asr.py`：SherpaOnnx SenseVoice 封装，懒加载 + 线程锁
- `packages/bridge-core/voice/tts.py`：TTSProvider 抽象（Edge 已实现 / CosyVoice2 留位）
- `packages/bridge-core/service.py`：stdlib HTTP 服务 127.0.0.1:8787，路由 /status /config /tts /asr /voice/loopback
- `packages/bridge-core/prep.ps1`：装 vendor 依赖（edge-tts/sherpa-onnx/soundfile/pilk/numpy）+ 拉模型
- 依赖装进 `packages/bridge-core/vendor`（不放 venv：wxauto 必须活在桥进程里），service.py 自己拼 sys.path

## 桥侧改造（wechat_bridge.py）
- 删除 `HUMAN_STYLE` 硬编码常量及其 3 处拼接（prompt 拼接 2 处 + run_agent 1 处）；
  说话风格现在只来自 `persona.md`（唯一真源仍是 config.json 的 persona.profile + strategy.*）
- 新增 `_start_control_service()`：在 `main()` 最前面、单实例锁之后，把 bridge-core 服务挂成守护线程；
  失败只写日志绝不影响桥。桥进程内跑服务的好处是 /status 能直接反映真实桥状态（pid/state）
- 坑：桥必须用 `C:\Users\one\.dsh\wxauto\venv` 的 python 启动（DSH runtime 的 python 缺 wxauto 依赖），
  用 `pythonw.exe keepalive_runner.py` 拉起即可（runner 用 sys.executable 续拉，所以解释器要选对）

## 验证
- `/status`：桥 pid 真实存活探测（Windows 不能用 os.kill(pid,0)，会 TerminateProcess，改 OpenProcess+GetExitCodeProcess）
- `/tts`：Edge TTS 生成 mp3，2568ms，"小肥鱼语音链路自检"
- `/voice/loopback`：TTS→wav→ASR 回环（模型下载完成后跑通）
